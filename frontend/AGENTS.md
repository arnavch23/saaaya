# Repository guide

## Project shape
- This is a Vite + React + strict TypeScript prototype. The active path is `index.html` -> `src/main.tsx` -> `src/App.tsx`.
- `src/App.tsx` owns the current view routing and dashboard composition; reusable UI lives in `src/components/`, domain logic/types in `src/data/` and `src/types/`.
- Root `App.tsx` and `PuneRiskMap.tsx` are legacy and outside the active TypeScript build. Do not use them as entrypoints; `PuneRiskMap.tsx` also references the undeclared `maplibre-gl` package.
- Tailwind runs through `@tailwindcss/vite`; Vite cache output is under ignored `work/`.

## Commands
```sh
npm ci
npm run dev
npm run build
npm run lint
```
- `npm run build` is the authoritative typecheck and production build (`tsc -b && vite build`).
- There is no test script, test framework, standalone typecheck script, formatter, or CI workflow. Use targeted browser checks for UI changes and the build for static validation.
- `npm run lint` currently fails before linting because no `eslint.config.*` exists. Treat that as the repository baseline; do not report lint as passing unless a config is added and the command succeeds.

## Heat-risk data
- `src/data/puneHistoricalWardRisk.ts` is generated by `scripts/build_historical_ward_risk.py`; never hand-edit it. Edit the generator and regenerate instead.
- The Python generator uses only the standard library and Open-Meteo ERA5-Seamless. Run it from the repository root with:
  ```sh
  python scripts/build_historical_ward_risk.py [--refresh]
  ```
- It reads `public/data/pune-electoral-wards-2022.geojson`, writes the generated TypeScript module, and caches raw responses in ignored `data/real-historical/`. Use `--refresh` to replace that cache.
- `--start` and `--end` are parsed but currently ignored: downloads are hard-coded to 1 March-31 May for 2024-2026. Fix the generator before relying on a different range, and refresh stale raw data after changing it.
- `src/data/historicalRisk.ts` applies a fixed ward-specific prototype exposure calibration after loading generated measurements. Displayed operational scores/categories can therefore differ from the raw generated `thermalRisk` and `riskLevel` fields.
- Weather inputs are real, but WBGT is explicitly a screening estimate, not instrument-measured occupational WBGT. Preserve that distinction in product copy.

## Runtime boundaries and prototype data
- Leaflet is the active map library. The ward map fetches `/data/pune-electoral-wards-2022.geojson`; keep that public path and its `wardnum` property alignment when changing boundaries.
- Map tiles come from OpenStreetMap at runtime, so map rendering needs network access even when the app is served locally.
- `src/data/mockHeatData.ts`, `mockHeatTrend.ts`, and `mockHeatLocalities.ts` supply simulated operational data. `2026-09-01` is a fixed prototype "today"; search all source files before changing date behavior.
- Authentication in `src/auth.ts` and `src/citizenAuth.ts` is browser-only prototype storage (`localStorage`/`sessionStorage`). There is no backend, real identity verification, or environment configuration; never treat submitted credentials as authenticated production data.
